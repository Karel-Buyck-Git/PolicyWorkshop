# Compute Policies

## Tier Rationale

**Essential — Managed disks, SKU governance, patching, encryption at host.**
The VM is still the workhorse of most Azure estates, so the baseline focuses on the hygiene that drives 80% of incidents: managed disks (not classic unmanaged storage), encryption at host (covers temp disk and disk caches that CMK alone misses), AAD-authenticated disk export/upload (no anonymous SAS leakage), automatic OS patching on Scale Sets, only approved VM extensions (the most common lateral-movement vector), a constrained SKU allowlist (FinOps + capacity governance), default antimalware deployed on Windows VMs, and ASR disaster-recovery replication configured. These map to ISO 27001 A.8.7 (data leakage), A.8.8 (vulnerabilities), A.8.24 (cryptography), A.5.30 (recovery), and NIS2 Article 21(2)(c) business continuity.

**Professional — Public access closed, antimalware operational, ARM migration.**
At this tier managed disks are no longer addressable from the public internet by default (private endpoints required), the Microsoft IaaSAntimalware extension is enforced and configured for automatic signature updates (someone must triage the resulting detections), and any remaining classic ASM virtual machines are required to migrate to ARM (which is what enables RBAC, managed identities, and the rest of the modern security stack). The antimalware family lives at Professional per the prompt's rule (threat protection requires someone to act on findings). This addresses NIS2 Article 21(2)(d)/(e) and CIS Microsoft Azure Foundations Benchmark §7 (VM).

**Enterprise — Disk-access private link, double encryption with CMK.**
Enterprise customers route managed disk access exclusively through Private Link / Private Endpoints with Private DNS zones (no public DNS resolution for disk operations like export, import, attach), and use double encryption — customer-managed keys layered on platform-managed keys via disk encryption sets — so a compromise of either key alone is insufficient. This combination meets ISO 27001 A.10/A.8.24 (cryptography), NIS2 Article 21(2)(h), and the data-sovereignty / "right to be forgotten" obligations of regulated industries where disk-level data residency must be provable.
