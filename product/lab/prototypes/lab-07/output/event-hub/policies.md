# Event Hub Policies

## Tier Rationale

**Essential — Identity governance and double encryption on the data plane.**
Event Hub ingests high-volume telemetry and event streams, often from sources that hold sensitive payloads. The baseline removes the most exploitable patterns: namespace-wide SAS keys replaced with entity-scoped authorization rules, local authentication disabled in favour of Microsoft Entra ID, and double encryption so data at rest is protected at both service and infrastructure layers. These map to ISO 27001 A.5.15 (access control), A.8.5 (secure authentication), and A.10/A.8.24 (cryptography), and align with NIS2 Article 21(2)(h) cryptography expectations.

**Professional — Public network access closed off.**
At this tier the namespace is no longer addressable from the public internet by default. Operations must maintain the allowed-IP and trusted-services list and respond when a producer legitimately needs a new path in. This is a network hardening control under NIS2 Article 21(2)(d) and CIS messaging-service recommendations.

**Enterprise — Private link, customer-managed keys, and SIEM-grade telemetry.**
Enterprise customers route Event Hub traffic exclusively through Private Link / Private Endpoints with Private DNS zones, encrypt at rest with customer-managed keys held in Key Vault (Event Hub requires dedicated clusters for CMK), and stream resource logs into Log Analytics or a downstream SIEM via diagnostic settings. This meets ISO 27001 A.12.4 (logging and monitoring), NIS2 Articles 21(2)(b) and 23 incident handling/reporting, and the data-sovereignty requirements typical for regulated event pipelines.
