## New findings

- **#52 — the renderers write host-native newlines, so `verify.sh` cannot pass on a Windows
  checkout.** `writeutil.py:15,23` use `Path.write_text` without `newline=`, which translates `\n`
  → `\r\n` on Windows (confirmed directly). Since `.gitattributes` (#45) added `* text=auto eol=lf`,
  the *working tree* is LF too — `eol=lf` overrides `core.autocrlf`, which #45's own comment reasons
  around ("only about the git-stored form" — it is not). So the byte-diff compares CRLF-generated
  bytes against LF-checked-out fixtures and fails. **It is currently intermittent, which is worse
  than broken**: the worktree is mixed (`git ls-files --eol` → 3842 `w/crlf`, 243 `w/lf`
  repo-wide; **25 vs 14** inside `examples/contoso/`), because a fixture last *written by the
  renderer* is CRLF and one last *written by git* is LF. That is why 07-25/26/27 sessions could
  legitimately report `verify.sh` green right after rebuilding fixtures, and why it fails today
  after the #48 merge re-checked those files out. **A fresh clone on Windows fails every text
  file.** Fix is one keyword in two places — `newline="\n"` in `write_json`/`write_text` — which
  also makes the output genuinely host-independent and costs **no fixture churn** (the committed
  fixtures are already LF). Consider the same for the producer writers for consistency; they are
  already immune via 27e's hash normalizer. *Low.*
- **#53 — the engine release step is undocumented and has never been run, so every shipped
  `lineage.json` under-reports the engine.** `release.py` appears in **no document in the repo** —
  `git grep` finds it only in `actions/backlog.md`, `reviews/` and `sessions/`, and
  `engine/tools/README.md` has neither an at-a-glance row nor a section for it, while it lists all
  eight other tools. This is the exact defect #51 opened for `catalogue_changelog.py`, one tool
  over, and #51 fixed only the changelog half. Consequence today: `version.py` says `0.1.0`, but the
  engine is 2 commits past `v0.1.0` including #48's behavioural guards, so `catalogue.json`
  `producedByEngine` and every package `lineage.json` `engineVersion` claim a build by an engine
  that did not produce them. `release.py` already proposes `0.2.0`; nothing tells anyone to run it.
  Fix: a `release.py` section + table row in `engine/tools/README.md`, and place the bump in the
  release sequence #51 is already going to write. *Low, and it should ride along with #51.* ✎
  Note the interaction: bumping the engine version changes `catalogue.json` `producedByEngine`, so
  the bump and a catalogue regeneration want to land together — same coupling #43/#22 hit.
