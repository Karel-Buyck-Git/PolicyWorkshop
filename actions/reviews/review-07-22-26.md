## Structure (how it actually runs)

- **Entry point:** [`engine/epac_builder/assemble_scaffold.py`](../../epac-workbench/engine/epac_builder/assemble_scaffold.py) —
  CLI: `--manifest <c>.manifest.jsonc [--input input.json] [--only json,terraform,bicep] [--check]
  [--strict] [--out <dir>]`. Pure deterministic transform: manifest + pinned catalogue → package.
- **Consumer/assembler pipeline:** `expand` → `catalogue.resolve(selection)` → `build_ir` →
  per-flavour `render_{json,terraform,bicep}` → `report` → `package.finalize`. ~8,800 LOC, **stdlib
  only** (no `pip install`, `dependencies = []`, Python ≥3.10).
- **Producer (catalogue-builder):** `engine/catalogue_builder/` phases 1–5 (`extract` → `enrich` →
  `create_initiatives` → `apply_overlays` → `quality_control`) build the versioned shared
  `catalogue/` (`2026.07.18`). Driven by `/catalogue-builder-run`, not the assembler.
- **Three ways to invoke:** CLI (above), the `/epac-builder-onboard` skill (interview → generate),
  and the stdio **MCP server** (`validate_manifest` today).
- **Empty-by-design consumer area** (`customer/` ships schemas + templates only) vs **worked sample +
  golden fixture** (`examples/contoso/`, regenerated never hand-edited).

## State — built vs. incomplete

- Producer: builds the versioned catalogue with provenance hashes. ✔

**Incomplete / stubbed / not-here:**
- **The json renderer this branch ships is rejected by EPAC 11.4.7.** The two fixes proven to make
  EPAC accept it (`desiredState.strategy` + `definitionEntry.policySetName`, **#20**) were **never
  committed to this repository** — verified across every branch tip, none carries them; they existed
  only as a manual patch in a consumer's local working tree on another machine. This is the single
  biggest gap between "generates a package" and "generates a deployable package."
- Deployability never proven in CI (byte-diff only); only ad-hoc consumer dry-runs (**#14**).
- Naming initiative hardcodes `customerAbbreviation:"dlw"` **162×** — audits every non-DLW customer
  against the wrong anchor (**#21**).
- No engine version (`0.0.0`), `hierarchyVersion` inert, `lineage.json` ships only `catalogueVersion`
  — a customer can't answer "which builder produced this?" (**#27**, blocks Alpha exit).
- Producer Phase 3 is append-only — a moved/removed group silently orphans on disk and corrupts
  `contentHash` (**#26**); must land before the next catalogue regen.
- terraform/bicep get no validator, PR gate, or setup guide (json only, **#33/#34**); ADO not
  generated (**#32**); no front end (**#31**); no producer CI / drift-sync / cloud update (#7/#8/#37).

   Do this first.
2. **#26 — Phase-3 GC.** *Low code* (mirror the existing `apply_overlays.py:120-128` prune). Land

3. **#21 — parameterize `customerAbbreviation` out of the naming initiative.** *Medium* (producer

4. **#27 — versioning/provenance model.** *High (decision spike first).* Blocks Alpha exit and any
   delivery to someone outside this repo — nothing can stamp `lineage.json`.
5. **#14 — prove real-tenant deployability in an opt-in workflow.** *High* (needs tenant + creds).
   #20 is the code half of this; #14 is the live proof.
6. **#38 — unit-test layer for engine modules.** *Medium, ongoing.* Golden-fixture regression is
   strong but coarse; module-level tests would localize failures the byte-diff only flags globally.
