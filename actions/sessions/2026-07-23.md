### #20 — EPAC renderer fixes so json packages actually deploy (done)

Root cause confirmed against live code: `render_json._assignment` emitted a flat top-level
`policySetDefinitionName` (EPAC hard-rejects: *"each tree branch must define a definitionEntry…"*),
and `_write_global_settings` emitted **no `desiredState`** (so EPAC defaults to the destructive
`full`, proposing deletion of a tenant's pre-existing policy). **Provenance correction:** the fix was
**never committed to this repo** — verified across every branch tip, none carried it; it had existed
only as a consumer's local hand-patch on another device (the earlier "another branch" wording in the
review/backlog was corrected).

The fix (json-only — tf/bicep emit native `azurerm`/ARM resources with no `desiredState`/`policySetName`
concept):
- **(a)** `desiredState` now emitted inside each `pacEnvironment` with a **brownfield-safe default**
  (`strategy:"ownedOnly"`, `keepDfcSecurityAssignments:false`); `strategy` (+ optional `excludedScopes`)
  added as a per-environment manifest field in **both** schemas and threaded through `ir._env`.
- **(b)** `_assignment` emits `definitionEntry.policySetName`.
- **Side-fix:** `pkgvalidate.check_references` read only `policySetDefinitionName` and skipped
  `definitionEntry`, so the shipped `validate-package.py` would have silently stopped checking
  assignment→policyset integrity — now reads both.

Regenerated the contoso json fixture (global-settings + 2 assignments + the verbatim validator copy).
**#20 → done**; opened **#39** (see below).
