# Session — 2026-07-06

## Done

- **Backlog #2 DONE — `--strict` deploy-ready gate.** The gap: structure validation
  (`manifest.schema.json`) proves a manifest is *well-formed*, not *filled in*. Most fields are free
  strings, so an unedited `<REPLACE: …>` (a selector, location, Log Analytics id, bound param value,
  metadata field) sails through and renders **verbatim** into the package, and a selection with no
  `managementGroup`/`scope` resolves to `PLACEHOLDER_SCOPE` — a `[warn]`, not an error. Azure only
  rejects both at deploy.

  **Implementation:**
  - New `flows/epac_builder/strict.py`: `residual_placeholders(manifest, ir)` (recursive walk of the
    manifest — flags placeholder string *values* and placeholder dict *keys* — plus a scan of the IR
    assignments for `PLACEHOLDER_SCOPE`) and `StrictGateError` (lists every problem with a JSON-pointer
    path, one message).
  - `assemble_scaffold.py`: `assemble(..., strict=False, ...)` + `--strict` CLI flag; the gate runs
    **right after `build_ir` and the warnings loop, before the `--check` return and any write**, so
    both `--check` and a full build honour it. `StrictGateError` added to the caught-exception tuple
    in `main()` (exit 2).

  **Design notes:**
  - The schema build-gate already catches the four *pattern-constrained* placeholders first
    (`prefix`, `tenantId`, `deploymentRootScope`, `enforcement`) with precise messages. `--strict`'s
    unique value is the *free-string* fields the schema structurally can't reach — verified it lists
    all **12** on a half-filled manifest (`hierarchyVersion`, `selector`, `managedIdentityLocation`,
    `logAnalyticsWorkspaceId`, `allowedLocations`, `notScopes` key+value, per-selection `scope` keys,
    3× `metadata`). So schema + strict together cover everything.
  - **Off by default** — partial scaffolds still build during authoring; `--strict` is the opt-in
    pre-deploy gate. `--check --strict` is the "is this manifest deploy-ready?" query (validate-only).

  **Verification (by hand, all four ends):**
  1. Fully-mapped manifest + `--check --strict` → **PASS** (exit 0).
  2. Contoso example (intentionally leaves `management/essential/tags` unmapped) + `--strict` →
     **FAIL** on exactly that placeholder scope (exit 2).
  3. Half-filled manifest (free-string placeholders remain) + `--strict` → **FAIL** listing all 12.
  4. Default non-strict build → **unchanged**: `verify.sh` still byte-identical on json+terraform+bicep.

  **Wired into the "deploy-ready" flows + docs:**
  - `verify.sh` gained a **regression guard**: contoso's unmapped `tags` selection means
    `--check --strict` must exit non-zero — CI now asserts the gate *fires* (fails loudly if `--strict`
    ever silently passes an incomplete manifest). Zero new fixtures.
  - Onboarding `SKILL.md` step 5 and the `epac-builder-start` health check now run `--check --strict`
    (the health check's customer-readiness probe).
  - `customer/manifests/README.md` gained a strict pre-build check step; `epac_builder/README.md`
    (entry block + at-a-glance table row + a `--strict` explainer paragraph) and
    `docs/epac-assembler-design.md` usage comment updated.

  This is the guardrail the reverted template-GUID slip (2026-07-05) called for.
