## Done

### #52a — the engine writes LF on every host

`newline="\n"` on every engine write. Consumer side (`writeutil.py`, which every renderer,
`report.py` and `package.py` write through, plus the `pacOwnerId` write-back and `--input`
expansion) is what restores the gate; `quality_control.py`, `scaffold.py` and all of
`tools/` got the same treatment so the rule is *"the engine writes LF, always"* rather than
a half-converted tree. `release.py` mattered most there — without it a bump run on Windows
rewrote `version.py` and `pyproject.toml` **entirely as CRLF**.

Also corrected the `.gitattributes` header comment, which is where this actually came from:
it asserted the file was "only about the git-stored form", but `eol=` is a *checkout*
attribute too. The wrong premise is what let the breakage ship.

**Split deliberately.** Exactly four engine files are fingerprinted into `catalogue.json`
`tools.*`, so editing them drifts the stamp and forces a regeneration — the same coupling
that cost a release in #43/#22/#48. Those four are **#52b**, batched with the next release.

**Verified:** `verify.sh` green on a Windows checkout for the first time since #45; all
three fixture trees regenerated in place produce **byte-identical** output, so the committed
fixtures never moved; stamp 9/9; MCP 5/5.

### #51 + #53 — the release procedure exists now

`/catalogue-builder-run` gained **Phase 6 — Release**, and "Done when" moved to the end of
it. Phases 1–5 left the repo with no changelog entry and contoso pinned to the previous
catalogue — i.e. a red build and, worse, a release invisible to #48's collision guard, whose
`version_collision` returns `None` for a label the ledger never recorded.

The two traps are written down rather than restated: **6.0** stage the old catalogue at a
**short** path before phase 3 rmtree's it (with #51's measured `MAX_PATH` numbers — the
obvious location has one char of headroom and every subdirectory overflows), and **6.1**
bump the engine **before** regenerating, because `producedByEngine` is stamped during phases
3–4.

`release.py` now has its row and section in the tools README, and the preamble flags it as
the one tool there that *writes* tracked files rather than only reporting.

**The bump is not cut.** `release.py` proposes `0.2.0`, but by its own new rule the bump
rides a catalogue regeneration — the **#52b + #49** batch. A known one-command gap now
instead of an invisible one.

### #38 + #44 — 117 unit tests

`unittest` only, `dependencies = []` untouched, ~0.2s, wired in as a fourth CI step.
`tests/fixtures/mini-catalogue/` is three hand-authored groups (plain / anchored /
remediating) of a few KB, pinning **no** catalogue version so a release never invalidates
it.

**#44 routed here rather than through the fixtures**, on Karel's call once the numbers were
on the table: the real naming initiative is **169 members / 111 KB**, so covering the anchor
path via contoso would commit **~330 KB** across three flavour trees — the policyset in
json, all 169 members inlined into terraform's `main.tf`, another copy for bicep — and
re-churn it on every naming-touching release, for a break that would *still* report as a
byte-diff.

`test_expand.py` is the deliberate exception: it drives the **real** catalogue and **real**
schemas, because half its job is proving the shipped schemas still accept what the shipped
code emits — precisely the pairing that broke in #42. It reads its selection from
`index.json` at runtime, so no group name is hardcoded.

**Both new guards were verified by breaking the code**, not by watching green: removing
`newline="\n"` → 3 failures; removing the anchor binding → 4 `BindError`s naming the key and
the manifest path. Producer *phase* tests remain open and are named as the remainder in
`tests/README.md`, rather than closing #38 on partial delivery.

### #14 — prep, ready for a tenant that has not cleared

Under `epac-workbench/docs/intake/` (maintainer plane, never ships). `tenant-intake.md` maps
every value to the exact manifest key it feeds with the **read-only** `az` command that gets
it — all 13 keys cross-checked against `manifest.schema.json` — so the tenant session is one
pass. It leads with the three decisions that are expensive to get wrong: `deploymentRootScope`
(EPAC owns it *and everything beneath*), greenfield vs brownfield driving
`desiredState.strategy`, and starting `Audit` because many hardened effects are `Deny` on
resources that are immutable after creation (#47b). Plus `hierarchy-file.md` (the shape
`load_mg_index` consumes, a converter from `az --expand --recurse`) and `oidc-checklist.md`
(order and traps only — the tables stay in the *shipped* guides, which are authoritative
because the customer holds them).

`epac-deploy-verify.yml` is `workflow_dispatch`-only, **plan/what-if only**, and gated on a
preflight job that *reports* rather than fails when secrets are absent — so it is committed
and green today. (Secrets can't be read in a job-level `if:`, hence preflight/outputs.)
`static-validation` always runs: a package failing its own Tier-1 validator isn't worth a
tenant round-trip.
