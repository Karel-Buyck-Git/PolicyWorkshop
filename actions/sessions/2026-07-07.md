- **Backlog #17 STARTED — `validate_manifest`, the first local MCP tool** (`33004ba`, pushed;
  `contoso epac build` green on it). New stdlib-only package `catalogue-builder/flows/mcp_server/`:
  - **Transport decision: hand-rolled, no `mcp` PyPI SDK.** `server.py` implements JSON-RPC 2.0 over
    newline-delimited stdio (`initialize`/`tools/list`/`tools/call`/`ping`) + a tool registry, so the
    project's `dependencies = []` stdlib-only contract holds (the alternative — adopting the `mcp`
    SDK — would have been the first third-party runtime dep; rejected). Forces UTF-8 stdio (Windows
    cp1252 would otherwise corrupt the protocol channel); stdout carries **only** JSON-RPC (engine
    logging is captured off it).
  - **Tool** `tools/validate_manifest.py` wraps `assemble_scaffold.py --check` / `--check --strict`,
    **imported (not shelled out)** — returns *structured* JSON (the CLI flattens the same detail into
    one stderr string): success → `{valid, initiativesResolved, warnings, note}`; failure →
    `{valid:false, errors|strictProblems|error}`. **Design: a validation failure is a normal result**
    (`isError:false`, `valid:false` + problem list); `isError:true` is reserved for real tool
    failures (bad path, crash) — this is what makes it usable feedback for an iterating agent.
  - **Read-only guard (engine touch):** threaded a `write_back=True` default through
    `resolve_pac_owner_id` / `load_manifest` / `assemble`; the tool passes `write_back=False` so
    validating never triggers the CLI's `pacOwnerId` GUID write-back — it surfaces a note instead.
    CLI defaults unchanged → `verify.sh` still byte-identical on all 3 flavours.
  - Registered for Claude Code via **root `.mcp.json`**. Path resolution is cwd-independent (relative
    manifest paths resolve against the catalogue-builder root, from `__file__`).
  - **Verified:** smoke test `flows/mcp_server/test_server.sh` (5/5 — initialize, tools/list, `--check`
