### #36 — folder renames: `catalogue-builder/` → `epac-workbench/`, `flows/` → `engine/` (done)

Two renames so each name does one job. End state:
`epac-workbench/engine/catalogue_builder` (producer) · `epac-workbench/engine/epac_builder` (consumer).
Name chosen with Karel: **`epac-workbench`** (over `workbench`/`policy-forge` — self-describing against
the `epac_builder` component); `pyproject.toml` `name=` field deferred.

**Why it was safe.** Exploration proved no code breaks: every module derives its root *relatively*
(`PROJECT_ROOT = parents[2]`, `flows_dir = Path(__file__).resolve().parent`, `CB_ROOT = parents[3]`) and
imports siblings by **bare package name** (`from shared.paths`, `from epac_builder import …`) — there is
**no dotted `flows.` import** and **no literal `"flows"`/`"catalogue-builder"` path join** anywhere, and
the rename preserves directory depth. So it's `git mv` + string sweeps + regeneration, not a refactor.
