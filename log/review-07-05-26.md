  package; it is **live and green in GitHub Actions** (backlog #1/#9).

  `__pycache__`/gitignore confirmed clean (#12/#1a/#1b).

## State — built vs. incomplete

- **Built & solid:** full consumer pipeline (expand → validate → resolve → bind → IR → 3 renderers
  → report/lineage), sole entry point `assemble_scaffold.py`. Stdlib-only, fail-fast, deterministic.
  Per-module READMEs + design docs remain unusually thorough.
- **Built:** producer end-to-end; catalogue committed (version `2026.06.21`); pinned reproducible
  source; CI green.
- **Incomplete / rough (unchanged from 07-03):**
  - Catalogue still ships **`undefined`-domain policies** (~25 index refs) and the
    **`builtinpolicytest`** junk group (4 files under `catalogue/initiatives/undefined/`) — #3 open.
  - **No manifest completion guardrail** (#2 open): unfilled `<REPLACE:>` *parameter* values and
    scope-less selections still pass the build gate and flow into output as a `[warn]` only. (Note:
    `<REPLACE:>` in *schema-patterned* fields — prefix, tenantId, rootScope, enforcement — **is**
    caught by the build-gate validator, as confirmed on the empty template.)
- **Nothing stubbed in the core path** — only intentional `<REPLACE:>` values remain.

## Functionality — does the core path work end-to-end?

**Yes, re-confirmed by running it today:**

- Build of `examples/contoso` → **byte-identical** to the committed fixture (`diff -rq`, exit 0).
  Determinism contract holds.
- `--only json,terraform,bicep` produced three self-contained packages (EPAC `Definitions/`,
  Terraform `azurerm` module + `environments/`, Bicep `main.bicep` + `policies/` + `docs/`), each
  with pipeline + README + `lineage.json` + `report.md`.
- `--check` on the empty `customer/manifests/manifest.template.jsonc` correctly **fails** at the
  build gate with 4 clear pattern errors — the scaffold-is-unfilled path behaves as intended.
- Scope-less selection surfaces the expected `[warn]` placeholder-scope message (the #2 gap).

## Readiness — could a real customer use this today?

**Closer than 07-03, but still alpha.** The engine works and a user can now start from a clean
scaffold. Remaining blockers, ranked by effort (lowest first):

1. **Manifest completion guardrail (#2)** _(medium, low-ish)._ Still the sharpest edge for a
   real user: a scope-less or unfilled-parameter manifest builds "successfully" and emits an EPAC
   package Azure rejects at deploy — the only signal is a `[warn]` line. Add a `--strict`/pre-deploy
   gate that fails when any `<REPLACE:>` or placeholder-scope survives into output.
2. **Terraform/Bicep renderers have zero regression coverage** _(low)._ CI only builds the default
   (json) flavour and diffs it; the `render_terraform` and `render_bicep` paths — which I exercised
   by hand — are protected by **no** test. A silent regression in either ships undetected. Extend the
   golden fixture to a `--only json,terraform,bicep` build + full-tree diff. (New finding — see #13.)
3. **Catalogue isn't customer-clean (#3)** _(highest)._ Curate the published catalogue: resolve/remove
   `undefined`-domain policies and drop `builtinpolicytest`, so a customer never selects into junk and
   the catalogue regenerates reproducibly. Data curation, not a quick fix.
