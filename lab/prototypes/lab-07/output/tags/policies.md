# Tags Policies

## Tier Rationale

**Essential — Required tags enforced at creation.**
Tagging is the foundation for cost allocation (FinOps), ownership tracking, environment separation, and downstream automation. The baseline enforces a required tag and value on every new resource and resource group via deny effects, and appends parent-context tags (e.g. from the resource group) when missing. Without enforced tags at creation, FinOps reporting, blast-radius analysis during incidents, and automated lifecycle policies all break. These map to ISO 27001 A.5.9 (inventory of information and other associated assets) and CIS Microsoft Azure Foundations Benchmark §1 governance recommendations.

**Professional — Active remediation of existing untagged or mistagged resources.**
At this tier modify-effect policies actively backfill tags onto existing resources via remediation tasks, and inherit tag values from the parent subscription or resource group. Someone has to own the remediation queue and resolve conflicts when an existing tag value differs from the policy-mandated one — that operational ownership is what places this work at Professional rather than Essential. This addresses the asset-management completeness expectations of ISO 27001 A.5.9 and NIS2 Article 21(2)(a) risk-management policy on asset inventory.

**Enterprise — Tag-driven regulatory and data-sovereignty controls.**
There are no built-in Azure tag policies that fit Enterprise by themselves, but the tagging foundation is what enables Enterprise controls in other categories: data-residency tags trigger location restrictions, data-classification tags trigger encryption and audit pipelines, and cost-centre tags feed regulatory financial reporting. Customers at Enterprise tier typically extend the built-in tag policies with custom definitions that enforce these regulatory taxonomies, aligning with NIS2 Article 21(2)(a) asset-management and ISO 27001 A.5.12 (classification of information).
