**Why this release happened.** Two engine changes, neither of which touches a policy — but both
of which move the fingerprints, so the catalogue had to be regenerated to stay in sync.

**Nothing you deploy changes.** Every policy, tier, category, group name and effect is identical
to `2026.07.26`; 3461 policies unchanged, 0 added, 0 removed, 0 re-tiered. If you are pinned to
`2026.07.26`, upgrading is a re-pin of `catalogueVersion` **and** `catalogueContentHash` and
nothing else.

- **The engine now writes LF line endings on every host** (#52). Previously the producer emitted
  the build machine's native newline, so a catalogue built on Windows and one built on Linux were
  byte-different for no semantic reason. `contentHash` was always immune (it normalises newlines
  before hashing), but the files on disk were not, and the consumer half of the same defect made
  the byte-for-byte regression gate unpassable on a Windows checkout. All four producer scripts
  are fingerprinted into `tools.*`, so fixing them necessarily moves those four hashes.
- **The category-abbreviation map is now stamped** (#49). `config/azure-category-abbreviation.md`
  was the fourth authored producer input and the only unstamped one — yet it feeds the naming
  engine that builds *every* catalogue technical name, so editing an abbreviation renames groups
  across the catalogue while every recorded provenance input stayed identical. A change to it
  would have been reported as "no attributable cause", pointing the reader at a determinism bug
  that did not exist. It now appears as `inputs.categoryAbbrevHash`, is verified by the CI stamp
  check (10 stamps, up from 9), and counts as a **taxonomy/curation** driver when it moves.

`contentHash` moved because each policy set records the catalogue version it was built from; the
policy content behind it is byte-identical.

The producer now refuses to stamp a version label this changelog already records for different
content (backlog #48). `catalogueVersion` defaults to the UTC date, so two releases in one day
collided on one label — and because the assembler's version pin is an exact string compare, a
package pinned to the morning catalogue would build green against the evening one. Phase 4
checks the label against this file before finalizing the stamp; phase 3 warns earlier, where
`--version` can still be corrected. Engine change only: the same 3461 policies in the same 188
groups, with the same effects and tiers.
